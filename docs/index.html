Irregular times. Regular bins.

Storage is a separate comparison.

TIX48 carries position and level in six native bytes. In this benchmark its BigUint64Array uses eight bytes per code, the same payload width as the numeric timestamp array.

Method, Python results, and the link to spectral analysis

A fixed seed generates the same random quarter-second observations across about 97 days, with a synthetic sinusoid plus noise. Source cells are L42, finer than the L27 output bins. No sample is assigned more precisely than its stored interval permits.

Each representation is prepared first. Date objects are created in batches of at most 8,192, then released. Timings exclude preparation, use a warmup and the median of three passes, and rotate method order between batches. Results verify every period count and every bin’s count and sum. Setup time is shown separately; timing noise and engine optimizations still matter.

These are specialized kernels over validated data: the TIX mask and query bounds are compiled once. Repeatedly validating or converting inputs inside the loop would measure a different workload. For one-off work, add conversion costs; repeated work can amortize them. Integer timestamps can also use dyadic shifts and grouping, and indexed queries can beat a full scan; a speedup here is not an exclusive capability of TIX.

In the reference Python 3.14.2 arm64 run with one million observations, grid preparation took 103.1 ms with TIX, 169.0 ms with datetime deltas, and 118.8 ms with Unix milliseconds. The simpler period count favored datetime (25.4 ms versus TIX’s 36.7 ms). JavaScript may give a different ordering. Read the measured Python results or rerun the standard-library Python benchmark.

The grid is preparation for an FFT; no FFT is timed here. An ordinary FFT operates on a uniformly sampled sequence. Binning changes the signal, so bin width, aggregation, weights and missing-bin treatment need a deliberate choice. TIX does not accelerate the transform itself or recover unknown timing within a coarse interval. For direct analysis of unevenly sampled observations, methods such as Lomb–Scargle are another option. See NumPy’s DFT conventions and SciPy’s Lomb–Scargle documentation.

KEEP THE PREFIX. CHANGE THE SCALE.

Fine detail.
Fast grouping.

A timestamp is assigned to an interval at the level you choose. To group at a coarser level, mask the finer prefix bits and update the level header. No calendar parsing. No scan through individual seconds.

These integer keys can make temporal grouping and filtering much faster. Use a coarser prefix as a MapReduce key or a time bucket for clustering, while retaining finer intervals in your data.

This is an efficient grouping primitive, not a clustering algorithm. Actual speed depends on the workload, storage and execution engine. The runnable comparisons above measure two specific cases.

TIX IS THE FAMILY

Choose the footprint.
Keep the hierarchy.

Six bits encode the level. The remaining bits hold a left-aligned time prefix. TIX48 is the default; TIX32 trades resolution for a smaller footprint, while TIX58 retains finer detail.

FormatMax levelFinest duration
TIX322616,384 seconds
TIX48 · default420.25 seconds
TIX5852244.140625 microseconds

All share the same 240-second domain, centered on the Unix epoch. Level 40 is always exactly one second wherever the chosen width supports it. TIX32 stops at level 26.

Width is external metadata. A code must be decoded with its width; raw integers are not interchangeable across widths. Exact conversion needs a level supported by both formats.

Complete tix.py. Core times use integer quarter-seconds by default. Use encode_seconds() for Unix seconds.

Includes encode/decode, hierarchy, containment, overlap, range covering, hex and Base64url. C defaults to TIX48; define TIX_BITS before including the header for another width. Python takes bits=48 by default.

Exact boundaries.
Honest precision.

TIX encodes a temporal interval, not an instantaneous event. A fine interval describes resolution, not the accuracy of an observation. A coarser interval may better reflect what is actually known.

Time is POSIX/Unix time. Leap seconds have no separate representation. Out-of-domain dates, invalid levels and noncanonical codes are rejected, never clamped.

The reference range cover is exact at the finest supported level. At a requested coarser limit it rounds outward, so it can include time outside the requested range.
